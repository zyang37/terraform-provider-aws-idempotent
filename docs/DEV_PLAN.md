# terraform-provider-aws-idempotent: Development Plan

Status: draft, 2026-09-15. Baseline: `hashicorp/terraform-provider-aws` **v6.64.0**
(Go 1.26.6, `aws-sdk-go-v2` v1.46.0).

## 1. Goal

A drop-in build of the AWS provider where every AWS API call that supports an
idempotency token gets a **deterministic, journaled** token instead of a random
one. If `terraform apply` is killed after a request reaches AWS but before
Terraform records the result in state, the next apply resends the **same**
token. AWS then returns the resource it already created, and no duplicate is
made.

### Non-goals (v1)

- Making operations without a token idempotent. See section 7.
- Changing any resource schema or plan behavior. Plans must be byte-identical
  to upstream.
- Replacing Terraform state or locking.

## 2. Verified facts the design builds on

|---|---|---|

| Smithy models mark tokens with `smithy.api#idempotencyToken`, with length and pattern limits. | `aws-sdk-go-v2/codegen/sdk-codegen/aws-models` | The supported list and token formats are generated, not hand-written. |

## 3. Your algorithm, made precise

The request asked for three steps: use an existing token, otherwise hash the API and arguments, then save the token locally. The precise version below adds four things that are needed for correctness.

1. **Treat provider random tokens as "absent".** The codemod replaces them with the sentinel `idempotency.AutoToken`.
   Any other non-empty token is a real caller choice and is kept.
2. **Add a sequence number.** Two `aws_instance` resources with `count = 2` send byte-identical `RunInstances` inputs.
   A hash alone would give both the same token, and AWS would return one instance twice.
3. **Reuse only tokens that are still `pending`.** A pending token was sent, but its response was never delivered.
   Reusing a *completed* token breaks destroy-then-recreate. It also breaks setting A, then B, then A again on an update API, because AWS would replay the old result.
4. **Salt per workspace.** Two workspaces deploying identical configs into one account must not share tokens.
   Without a salt, they would adopt each other's resources.

```
key   = SHA256( canonical{ partition, account, region, service, operation,
                           resource_type, input_without_token_field } )
token = format( HMAC-SHA256(workspace_salt, key || seq) )   // UUID / hex32 / hex64 per op table
```

`seq` is the lowest sequence number for `key` whose journal entry is pending and not claimed by a live process. If no such entry exists, `seq` is one more than the highest existing sequence number.

## 4. Architecture

```
terraform core ──gRPC──▶ [A] ApplyResourceChange wrapper (sets call scope, commits journal on delivery)
                              │
                              ▼
                     upstream resource code (codemod: random token → AutoToken sentinel)
                              │  client.RunInstances(ctx, input)
                              ▼
        aws-sdk-go-v2 stack:  Initialize: [B1] mark ─▶ OperationIdempotencyTokenAutoFill (skips; non-empty)
                              Serialize:  [B2] resolve token ─▶ journal [C] ─▶ OperationSerializer
                              Finalize:   retry loop (same token on every attempt)
                              Deserialize: ◀── response ── [B2] records outcome
```

### 4.2 Middleware flow

**B1, Initialize step.** It is inserted before `OperationIdempotencyTokenAutoFill`, or added first when that ID is absent, as in Tier 2.

```go
spec, ok := opTable[typeKey(in.Parameters)]        // reflect: PkgPath + "." + Name
if !ok || !spec.NameIsToken { return next(...) }   // 45 traited members like runtimeSessionId keep SDK behavior
f := field(in.Parameters, spec.Field)              // *string
switch {
case f == nil || *f == "":       *f = AutoToken; ctx = withAuto(ctx)   // absent
case *f == AutoToken:            ctx = withAuto(ctx)                   // codemod sentinel
default:                         /* caller-chosen token: keep */       // your step 1
}
```

**B2, Serialize step.** It is inserted before `OperationSerializer`. Region and service metadata are resolved by this point.

```go
if !isAuto(ctx) { return next(...) }
key   := hashKey(scope(ctx), in.Parameters, spec.Field)   // token field zeroed before hashing
entry := journal.ClaimOrCreate(key)                       // fsync'd BEFORE the request leaves
*f     = format(spec.Format, hmac(salt, key, entry.Seq))
out, md, err := next(...)                                 // includes all SDK retries
switch classify(err) {
case ok:            journal.MarkResponded(entry, summarize(out), callScope(ctx))
case apiRejected:   journal.MarkFailed(entry, err)        // 4xx validation: token is burned, never reuse
default:            /* timeout, ctx canceled, conn reset: stay pending */
}
```

**A, gRPC wrapper.** It covers `ApplyResourceChange` only.

- **Before the call:** it puts a call scope into `ctx` with the resource type and a call ID.
- **After the handler returns:** if `ctx.Err() == nil`, it promotes the `responded` entries for that call ID to `completed`.
- **If Terraform is gone:** a cancelled context usually means Terraform was killed or interrupted. The entries go back to `pending`, because Terraform never got the result.

This closes the window where the provider process outlives a killed Terraform.

### 4.3 Canonical input hashing

- **What is encoded:** exported fields in declaration order.
- **Maps:** keys are sorted.
- **Empty values:** `nil` and empty slices or maps are treated as equal. Pointers are dereferenced.
- **Special types:** `time.Time` becomes RFC 3339 in UTC, and `[]byte` becomes base64.
- **Token field:** it is zeroed first.
- **Streaming inputs:** an input with an `io.Reader`, or an unsupported `document.Interface`, is not hashable. The call falls back to the SDK's random token and logs a warning.
- **Stability rule:** the encoding version is part of the key. Any change to the encoder bumps the version.

### 4.4 Journal

**Location.** The default path is `.terraform/aws-idempotency/journal.db`. Terraform runs providers in the working directory, and `.terraform/` is already gitignored. It can be overridden by `idempotency { journal_path = ... }` or `TF_AWS_IDEMPOTENCY_JOURNAL`.

```sql
CREATE TABLE meta    (k TEXT PRIMARY KEY, v BLOB);            -- workspace_salt, schema_version
CREATE TABLE entries (
  key        TEXT, seq INTEGER, token TEXT,
  service    TEXT, operation TEXT, resource_type TEXT,
  state      TEXT CHECK (state IN ('pending','responded','completed','failed')),
  claimed_by TEXT,                 -- "<pid>:<process start time>"
  call_id    TEXT, summary TEXT,   -- response IDs/ARNs for orphan reports
  created_at INTEGER, updated_at INTEGER,
  PRIMARY KEY (key, seq)
);
```

**Settings.** The journal uses WAL mode with a busy timeout. Each provider alias runs as its own plugin process, so several processes may share one file.

**Claiming.** A claim is one transaction. It picks the lowest-`seq` entry that is `pending` and whose `claimed_by` process is dead. If there is none, it inserts a new entry.

| State | Meaning | Reusable on next apply? |
|---|---|---|
| `pending` | The request may have reached AWS, but no result was delivered to Terraform. | **Yes.** This is the crash-recovery path. |
| `responded` | AWS answered, but Terraform has not received it yet. | Becomes `pending` if delivery fails, otherwise `completed`. |
| `completed` | Terraform received the result. | No. |
| `failed` | AWS rejected the request. | No. |

**Garbage collection.** `completed` and `failed` entries are deleted after `retention`, which defaults to 7 days. When a `pending` entry is older than `orphan_warning_after`, which defaults to 24 hours, the provider logs a warning. The warning lists service, operation, and resource type, so a human can find a possible orphan.

### 4.5 Provider configuration

```hcl
provider "aws" {
  idempotency {
    enabled              = true                      # default true
    journal_path         = ".terraform/aws-idempotency/journal.db"
    retention            = "168h"
    orphan_warning_after = "24h"
  }
}
```

## 5. Behavior walkthrough

| Scenario | Upstream provider | This provider |
|---|---|---|
| **The crash case.** An apply creating `aws_instance.a` is killed after `RunInstances` was sent. Apply is run again. | New random token, so a second instance is created. The first one is orphaned. | The entry is `pending`, so the same token is sent. EC2 returns the original instance, and it is written to state. |
| `count = 2` with identical arguments | Two instances | Sequence numbers 0 and 1 give two tokens and two instances. |
| Crash with `count = 2`, both sent | Four instances after re-apply | Both pending entries are reclaimed, so there are two instances. |
| Destroy, then apply again the same day | New instance | Old entries are `completed`, so a new sequence number is used and a new instance is created. |
| Update A, then B, then A again, for example EKS `UpdateClusterConfig` | Applied three times | Each update gets a new sequence number, so each one is applied. |
| Config edited after the crash, before re-apply | Duplicate | Also a duplicate, because the hash differs. The pending entry is reported as a possible orphan. |
| Two workspaces with identical configs in one account | Independent | Independent, because the salts differ. |
| Journal deleted, or a fresh CI runner | n/a | Same as upstream, with random-equivalent tokens. It is safe but gives no protection. |
| An AWS 4xx validation error | Error | Error. The entry is `failed`, and a fixed config gets a new token. |

## 7. Known limitations (state these in the README)

1. **Most create APIs have no token.** The provider calls 1124 create-like operations.
   Only 340 of them accept a token.
   - **Name-unique resources** such as IAM roles, S3 buckets, SQS queues, and RDS instances fail on retry with "already exists" instead of duplicating. The user then imports them. That is annoying but safe.
   - **Nameless resources** still duplicate on crash. Examples are EC2 `CreateVpc`, `CreateSubnet`, `CreateInternetGateway`, `AllocateAddress`, and KMS `CreateKey`.
   - **Follow-up:** a tag-based adoption layer. Stamp a deterministic tag at create, and look it up before creating.
2. **Delivered but not persisted.** Terraform may receive the response and then be killed before it writes state.
   The provider cannot see this. When state is persisted depends on the backend and timing.
3. **Non-deterministic inputs.** `name_prefix` generates a random name on each run, so the hash changes and there is no protection.
   **Follow-up:** derive `create.PrefixedUniqueId` deterministically from resource type plus a config hash, behind a flag.
4. **Token lifetime is service-defined.** It is often around a day, and some services keep tokens longer.
   Re-applying after the token expires behaves like upstream. Record the per-service lifetime in `SUPPORTED_APIS.md` as it is verified.
5. **Local journal.** CI runners with ephemeral disks get no protection until the remote backend lands.

## 8. Test plan

### 8.1 Unit tests (`internal/idempotency`)

- **Canonical hasher.**
  - Golden files for representative inputs: `RunInstancesInput` with nested block devices, EKS `CreateClusterInput`, and a map-heavy input.
  - A property test that encodes the same value twice and gets equal bytes, across shuffled map insertion orders.
  - A test that `nil` and empty values hash the same, and that the token field never affects the hash.
  - A fuzz test (`go test -fuzz`) that feeds random structs and expects no panic.
- **Formats.** For every row in the op table, generate a token and check it against the member's length and pattern. The pattern is copied into the generated table and checked with Go `regexp`. This catches bad `FormatUUID`, `FormatHex32`, or `FormatHex64` choices across all 1609 operations.
- **Journal state machine.**
  - A table-driven test of every transition.
  - A test that claiming picks the lowest pending sequence number.
  - A test that entries claimed by a live process are skipped, and entries from a dead PID are reclaimed.
  - Garbage collection and orphan reporting.
  - Salt is created once and is stable.
- **Multi-process journal.** Spawn N helper processes with `os/exec` of the test binary. They issue M identical claims at once. Expect exactly N×M distinct tokens, no errors, and no duplicate `(key, seq)`.
- **Crash durability.** Kill a helper process with SIGKILL between `ClaimOrCreate` and the send. The entry must exist and be `pending` on reopen.

### 8.2 SDK middleware integration (no AWS, no Terraform)

- **Fake endpoint.** An `httptest.Server` implements token semantics: it stores token → response, replays the stored response for a known token, and returns `IdempotentParameterMismatch` when the same token arrives with a different body.
  Build real clients with `ec2.NewFromConfig(cfg)` and `BaseEndpoint` set to the server. This follows the upstream `apicall_e2e_test.go` pattern.
- **Cases.**
  - An empty token becomes deterministic, and the SDK auto-fill is not used.
  - A caller-set token passes through unchanged.
  - The `AutoToken` sentinel is replaced.
  - The same token is sent on every SDK retry. Force this with 500 responses.
  - Tier 2, where the SDK has no auto-fill, still gets a token. ECS `CreateService` is the example.
  - ACM gets 32 hex characters.
  - The region is part of the scope.
  - `NameIsToken=false` members keep SDK behavior.
- **Middleware order guard.** A test fails if `OperationIdempotencyTokenAutoFill` or `OperationSerializer` IDs change in a new SDK release.

### 8.3 Codemod tests (`tools/codemod-tokens`)

- **Golden tests.** `testdata/in/*.go` and `testdata/out/*.go` cover struct literals, field assignment, single-use variables, reused variables marked MANUAL, excludes, and import add and remove.
- **Idempotence.** Running the codemod twice gives no diff on the second run.
- **Upstream gate in CI.**
  - After each sync, run the codemod.
  - Require that `go build ./...` succeeds.
  - Require that `rg 'Token.*create\.UniqueId|Token.*sdkid\.'` finds nothing outside the reviewed MANUAL list.
  - Require that `REWRITE`/`MANUAL` counts changed only in reviewed ways. Commit the report.

### 8.4 Crash-recovery end-to-end (local, hermetic, runs in CI)

**Harness.** A Go test drives the real `terraform` CLI with a `dev_overrides` CLI config pointing at the built provider binary.
It sets `AWS_ENDPOINT_URL_*` to a local AWS emulator.

- **Emulator choice.** Before choosing between LocalStack and Moto, check how each handles `ClientToken` for the operations under test. A proxy in front of the emulator can supply token semantics where the emulator lacks them.
- **Unit-level alternative.** The 8.2 fake endpoint can be extended to the few operations used here.

**Fault injection.** It is compiled in only with the build tag `idemfault`. It is set with `TF_AWS_IDEMPOTENCY_FAULT=<service>:<Operation>:<point>`.

| Point | What happens | What it simulates |
|---|---|---|
| `after-journal` | SIGKILL self after the fsync, before the send. | Crash before the request left. |
| `after-send` | SIGKILL self in Deserialize, before the response is read. The request has reached the server. | **The target scenario.** |
| `after-response` | SIGKILL self after `MarkResponded`, before the handler returns. | Response received, not delivered. |
| (external) | The harness sends SIGKILL to the `terraform` process at a random delay. | A real user or CI kill. |

**Crash matrix.** Each row runs apply, crash, apply, then asserts the emulator contents. Assertions count instances or resources by a unique test tag, check state has exactly the expected addresses, and check that the final `terraform plan` shows no changes.

| Config | Fault | Expected after re-apply |
|---|---|---|
| 1 `aws_instance` | `after-send` | 1 instance, state has 1 |
| 1 `aws_instance` | `after-response` | 1 instance |
| `aws_instance` `count = 3`, identical | `after-send` on the second call | 3 instances |
| `aws_ebs_volume` and `aws_route_table` | external SIGKILL at random time, repeated 50 times | exactly 1 of each |
| `aws_ecs_service` (Tier 2) | `after-send` | 1 service |
| Destroy, then apply | none | new resource ID, old one gone |
| Update A, B, A (`aws_instance` credit spec) | none | final value A on the resource |
| Edit config after crash | `after-send` | 2 resources, and `journal orphans` lists 1 |
| `enabled = false` | `after-send` | 2 resources, the upstream baseline, proving the test detects duplicates |

The `enabled = false` row is the control. It must fail the "exactly one" assertion, which proves the harness can observe duplicates.

### 8.5 Real AWS acceptance (sandbox account, manual or nightly)

- **Resources.** Pick cheap nameless resources where duplicates are really observable: `aws_instance` (t4g.nano), `aws_ebs_volume` (1 GiB), `aws_route_table`, `aws_network_acl`, `aws_launch_template`, `aws_ecs_service` on Fargate with `desired_count = 0`, and `aws_route53_health_check`.
- **Tests.** Run the 8.4 matrix rows for `after-send` and external SIGKILL. Assertions query AWS directly with `DescribeInstances` and friends, filtered by a run-unique tag.
- **Cleanup.** A tag-based sweeper runs after each test, whatever the outcome.
- **Upstream regression.** Run the upstream `TestAcc` tests for resources whose files the codemod touched, for example `TestAccEC2Instance_basic`, `TestAccEC2EBSVolume_basic`, `TestAccACMCertificate_emailValidation`, and `TestAccEKSCluster_basic` (nightly only, because of cost). With `enabled = true`, results must match upstream.

### 8.6 Upgrade safety

- **Scheduled CI job.** It runs weekly. It fetches the latest provider tag and the matching SDK models, regenerates `ops.json`, the Go table, and the docs, then runs the codemod and all of 8.1 through 8.4.
- **On success**, it opens a PR with the diff, including the supported-API diff.
- **On failure**, the PR is opened as a draft. Typical causes are a new MANUAL site or changed middleware IDs.

## 9. Tooling already in this repo

```bash
# 1. Fetch inputs
git clone --depth 1 --filter=blob:none --sparse https://github.com/aws/aws-sdk-go-v2.git sdk
(cd sdk && git sparse-checkout set codegen/sdk-codegen/aws-models)
git clone --depth 1 --branch v6.64.0 https://github.com/hashicorp/terraform-provider-aws.git upstream

# 2. Generate the op table, docs, and Go map
M=sdk/codegen/sdk-codegen/aws-models
python3 tools/gen-idempotent-ops/gen.py $M --provider-dir=upstream > data/ops.json
python3 tools/gen-idempotent-ops/gen.py $M --provider-dir=upstream --markdown > docs/SUPPORTED_APIS.md
python3 tools/gen-idempotent-ops/gen.py $M --go | gofmt > upstream/internal/idempotency/zz_ops_gen.go

# 3. Rewrite random tokens (dry run prints a TSV report; -w writes)
(cd tools && go run ./codemod-tokens -provider ../upstream -ops ../data/ops.json \
    -exclude codemod-tokens/exclude.txt -w) > codemod-report.tsv
```
